# Сборка, запуск и использование

## Состав репозитория

```
prototype/            веб-часть игры (vanilla JS, без сборщика) — единственный источник кода игры
  index.html, css/, js/, fonts/, img/own/
  emulator.html       пульт эмулятора для второго устройства
  tools/relay.mjs     ретранслятор пульта → игры (Node 18+, без зависимостей)
mobile/               мобильная оболочка Capacitor 7
  capacitor.config.json, package.json
  android/            нативный проект Android (deep link kineta://train, иконка, заставка)
  scripts/copy-www.mjs  копирует prototype/ → mobile/www (только файлы игры)
  scripts/build-apk.ps1 сборка APK
  dist/               готовые APK
tests/
  unit/               юнит-тесты на node:test — конвейер сигнала, Bluetooth-мост, сохранения, стресс всех игр
  e2e/cdp.mjs         общая обвязка: headless Chrome через DevTools Protocol
  e2e/smoke.mjs       сквозной прогон, скриншоты в tests/e2e/out/
  e2e/monkey.mjs      фаззинг сохранений, deep link, postMessage, пакетов и случайные нажатия по всем экранам
  e2e/screencast.mjs  демонстрационный ролик: тур по игре с ботом и подписями, склейка ffmpeg
tools/serve.mjs       статический сервер без зависимостей
docs/                 документация
package.json          npm test · test:unit · test:e2e · test:monkey · serve · serve:lan · apk
```

## Тесты

```bash
npm run test:unit   # ~30 с: 63 теста, без браузера (стресс игр — основная часть времени)
npm run test:e2e    # ~6 мин: Chrome/Edge headless, 33 сценария, 0 ошибок консоли
npm run test:monkey # ~3 мин: 30 сценариев — повреждённые сохранения, мусорные deep link, postMessage и пакеты, 700 случайных нажатий
npm test            # все три набора
node tests/e2e/monkey.mjs 2000 42   # больше действий и своё зерно (воспроизводимо)
node tests/e2e/screencast.mjs       # демо-ролик с подписями → docs/media/kineta-demo.mp4 (нужен ffmpeg, FFMPEG=путь)
```

## Голос: озвучка нейросетевым голосом Piper

Подсказки в игре и комментарии к ролику озвучиваются офлайн-синтезатором [Piper](https://github.com/rhasspy/piper) (лицензия MIT) — живой голос вместо системного «робота». Нужны `piper.exe` и голос `ru_RU-<голос>-medium.onnx` с [rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices) в одной папке (по умолчанию `C:/kineta-build/tts`, другая — `PIPER_DIR`).

```bash
node tools/voiceover.mjs game irina   # фразы игры → prototype/audio/voice/*.mp3 + index.json (попадают в APK)
node tools/voiceover.mjs cast irina   # комментарии ролика → tests/e2e/out/voice/*.wav
node tests/e2e/screencast.mjs         # ролик: подписи держатся, пока звучит фраза, звук сводится по отметкам времени
```

Голоса: `irina` (женский, по умолчанию), `denis`, `dmitri`, `ruslan` (мужские). Тексты комментариев — `tests/e2e/narration.mjs` (`text` — подпись, `say` — для речи, без сокращений). Фразы игры собираются из кода (`tools/voice-phrases.mjs`), поэтому после правки подсказок достаточно перезапустить `voiceover.mjs game`. В профиле: «Голос» — «Записанный» (Piper) или «Системный» (лучший русский голос телефона: нейросетевой → Google → остальные). Фраза без записи всегда звучит системным голосом.

Юнит-тесты загружают `js/native.js`, `js/core.js` и `js/games.js` в изолированный `vm`-контекст с искусственными часами: время сдвигается шагами по 10 мс, поэтому задержка, потеря пакетов и джиттер измеряются точно и воспроизводимо. Для e2e нужен установленный Chrome или Edge (путь можно задать переменной `CHROME`).

## Android: установочный APK

Требуется:
- Node.js 18+;
- JDK 21: подходит встроенный в Android Studio, `C:\Program Files\Android\Android Studio\jbr`;
- Android SDK с platform 35 и build-tools 35.

```powershell
cd mobile
npm install
npm run apk                      # = powershell -File scripts/build-apk.ps1
# → mobile/dist/kineta-3.5.1-debug.apk
```

Что делает скрипт:
1. Копирует игру в `www` и выполняет `npx cap sync android`.
2. Зеркалирует проект в `C:\kineta-build`. Gradle и AAPT2 нестабильно работают с путями не на латинице, а путь к проекту содержит «Антоха».
3. Собирает APK через `gradlew assembleDebug`.
4. Копирует APK в `mobile/dist`.

Параметры скрипта: `-Sdk`, `-Jdk`, `-Work`, `-Type release`. Release-сборку нужно подписать своим ключом.

Установка на телефон:
- `adb install -r mobile/dist/kineta-3.5.1-debug.apk`;
- или скопировать APK на телефон и открыть его, разрешив установку из неизвестных источников.

Минимальная версия — Android 8.0 (API 26). Размер APK — несколько мегабайт при ориентире 100–150 МБ.

Другой способ: `npx cap open android` в каталоге `mobile`, затем Build → Build APK в Android Studio.

### Нативные плагины

| Плагин | Зачем |
|---|---|
| `@capacitor-community/bluetooth-le` | Bluetooth LE к протезу. Во встроенном браузере Android и iOS нет Web Bluetooth, поэтому `js/native.js` собирает поверх плагина `navigator.bluetooth` с тем же API — драйвер протеза в `core.js` не меняется. Разрешения `BLUETOOTH_SCAN/CONNECT` плагин добавляет в манифест сам |
| `@capacitor/haptics` | Вибрация (на iOS `navigator.vibrate` нет) |
| `@capacitor-community/text-to-speech` | Голосовые подсказки на русском |
| `@capacitor/status-bar` | Цвет статус-бара под светлую и тёмную тему |
| `@capacitor/filesystem` + `@capacitor/share` | Экспорт данных и отчёт для специалиста: в WebView скачивание через `<a download>` не работает, поэтому файл пишется в кэш и отдаётся системному меню «Поделиться» |

В браузере каждая функция откатывается на веб-API (Web Bluetooth, `navigator.vibrate`, `speechSynthesis`, Blob).

## iOS

```bash
cd mobile && npm install && npx cap add ios && npx cap sync ios && npx cap open ios
```

Для iOS нужен Mac с Xcode. В `ios/App/App/Info.plist` добавьте схему для интеграции:

```xml
<key>CFBundleURLTypes</key><array><dict>
  <key>CFBundleURLSchemes</key><array><string>kineta</string></array>
</dict></array>
<key>NSBluetoothAlwaysUsageDescription</key>
<string>Kineta подключается к протезу, чтобы получать сигнал мышц</string>
```

## Веб-версия для отладки

```bash
npm run serve        # http://127.0.0.1:3000/ — tools/serve.mjs, без npx и зависимостей
npm run serve:lan    # открыть с телефона: http://<IP компьютера>:3000/
```

Управление в эмуляторе:
- **F** — К1, **J** — К2, **F+J** — обе мышцы. Если держать клавишу, сила нарастает.
- **1–4** — пронация, супинация, приведение, отведение (СПППР на 6 жестов).
- На панелях эмулятора высота точки касания задаёт силу.
- Кнопка «Обрыв связи на 2.5 с» проверяет инерцию и критическую потерю сигнала.

Параметры URL: `?reset=1` сбрасывает данные, `?embed=1` скрывает панель эмулятора, `?demo=1` заполняет дашборды демо-историей за 5 недель (для показа; на экранах появляется плашка «Демо-данные», `?demo=0` её убирает). Без флага новый пользователь начинает с пустой статистики. Также работают параметры интеграции из [INTEGRATION.md](INTEGRATION.md).

## Эмулятор на втором устройстве

Организаторы советуют эмулировать сигнал не из самой игры. В этом режиме экранные панели в игре скрыты, и управление идёт только «мышцами» с пульта.

1. На компьютере запустите `node prototype/tools/relay.mjs`. Он покажет адрес вида `http://192.168.1.5:8787`.
2. На втором телефоне откройте этот адрес. Это пульт с панелями К1/К2, порогами 0…255 и жестами СПППР.
3. В игре откройте Датчики → «Удалённый эмулятор», введите тот же адрес и нажмите «Подключить».

Пакеты пульта соответствуют контракту из INTEGRATION.md. Игра сама переключается между ЭМГ и СПППР по формату пакета.

## Использование

1. **Онбординг.** Три слайда, затем разрешения Bluetooth и геолокации; их можно пропустить, тогда работает демо-протез.
2. **Датчики.** Здесь выбирается:
   - поток: ЭМГ или СПППР;
   - режим одновременной активации;
   - источник порогов: свои игровые или из протеза;
   - словарь СПППР: 2 или 6 жестов.

   Пороги можно двигать прямо на графике. Тут же калибровка, чувствительность и тонкая настройка: сглаживание, dead-zone, гистерезис, подавление ложных срабатываний.
3. **Игры.** Сначала «Школа управления» (режим обучения), затем 7 игр по 3 уровня и бесконечный режим. Следующий уровень открывается за звезду.
4. **Прогресс.** Точность, чистота сигнала, баланс каналов, реакция, минуты и рекорды. Кнопка «Отчёт для специалиста» сохраняет HTML-отчёт за выбранный период (открывается на любом устройстве, печатается в PDF).
5. **Профиль.** Тема (светлая / тёмная / системная), цвет руки, крупный режим, формы каналов, проверка датчиков перед игрой, сторона протеза и зеркальный интерфейс, длина сеанса (5–20 мин), звук, вибрация, голосовые подсказки, отзыв, экспорт данных.
